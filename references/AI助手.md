# 页面里的 AI 助手（默认关，可选）

日常用法是在 Codex 里说、工作台开在 Codex 右侧面板，见 [接进Codex.md](接进Codex.md)。这一份只讲工作台页面里的那个对话栏：**默认关着，搭建时不打开、不演示、不作为主用法**（2026-11-12 定）。老板自己想在网页里直接问，再到“设置 → AI 助手”打开。

## 它是什么

打开以后，每页右下角多一个“AI 助手”按钮（⌘J / Ctrl+J）。它知道老板正在看哪一页，后台调**老板自己电脑上的 Codex**（用他自己的账号），挂的是和 Codex 插件同一套工作台工具（`server/assistant/mcp.ts`）：

- 读：今日、待办、日程、项目、客户、应收、模块……（`workbench_read`）和知识库（`kb_list`、`kb_read`、`kb_search`，只读）。
- 写：待办、日程、项目和里程碑、收件箱、跟进、答应的事、关怀草稿（`workbench_write`），一张清单一次写（`workbench_apply`，先预演、老板确认后再写）。导入、撤销、改设置、备份、提醒设置不开放。
- Codex 那边只读沙箱、关掉命令行、浏览器、插件和技能，不读老板 Codex 的个人配置；用了没开放的能力就停。写入记进“最近改动”，操作人是 Codex。
- 规矩写在提示词里（`server/assistant/runner.ts`）：待办问清谁做、哪天前；报价、合同、收款、承诺、改阶段先问，点头再写；改知识库原文不在这里做，交给 Codex 用 boss-kb。

关着的时候：按钮和快捷键都不出现，其他功能照常。打开了但本机没有 Codex、没登录：对话栏里会说清怎么办。

## 老板说“打开页面里的 AI 助手”

到“设置 → AI 助手”打开开关（或 `PATCH /api/settings` 写 `assistant_on: "1"`）。先跑 `node scripts/codex-check.mjs` 看本机 Codex 能不能用，结果怎么跟老板说见 [接进Codex.md](接进Codex.md) 的表。

## 已经验证的和还没验证的（2026-10-15）

- 已在 Mac 上实测：命令行版 `codex-cli 0.159.3` 和 Codex 桌面版自带的 `0.162.0-alpha` 都能用；读待办、读知识库、新加待办、加里程碑都跑通，页面自动刷新。
- 现在的模型只在“代码模式”里调工具，所以要打开 `code_mode_host`；不同版本的功能开关名单不一样，程序先 `codex features list`，只传这台 Codex 认识的开关。
- 还没测：Windows（桌面版自带命令行的位置、沙箱）；账号的额度够不够天天在工作台里问；2026-11-12 改成“先预演、确认后再写”以后，对话栏里跨两轮确认的真实跑一轮。
