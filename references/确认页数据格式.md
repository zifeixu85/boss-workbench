# 确认页数据格式

确认页只认两个文件，都放在工作目录（一般是 `<知识库根目录>/工作台/搭建确认/`）：

- `recommendations.json`：Skill 写，页面读。
- `result.json`：老板点“确认”后页面写，Skill 读。

完整例子：`scripts/confirm_ui/example/recommendations.json`（ABC茶社）。

## recommendations.json

```jsonc
{
  "version": 1,
  "boss": { "call": "林总", "business": "ABC茶社" },          // 称呼用知识库里的
  "kb": {
    "files": 31, "minutes": 2, "entry": "AGENTS.md",
    "layers": [{ "name": "02-关于我", "count": 5 }]           // kb_scan 的结果，显示在右侧“我读了什么”，最多放 9 行
  },
  "profile": [                                                // 六块复述，见 复述规则.md
    { "id": "who", "title": "你是谁、做什么", "text": "……", "sources": ["02-关于我/基本情况.md"] }
  ],
  "notes": [                                                  // 我注意到的，最多 3 条；level: info | warn
    { "id": "conflict", "level": "warn", "text": "……", "sources": ["05-方法与判断/企业茶礼报价与接单/判断规则.md"] }
  ],
  "wants": [                                                  // “早上最想先看到”的选项（可省略，省略时第二步不显示这一行）；module 填对应模块 id，点了会自动把模块放进来
    { "id": "sales", "label": "昨天各平台卖得怎么样", "selected": true, "module": "biz" }
  ],
  "modules": [
    {
      "id": "clients", "name": "客户跟进", "group": "生意",     // group: 首页 | 每天用 | 生意 | 内容 | 资料
      "status": "recommended",                                // recommended | optional | lacking | later
      "selected": true, "locked": false,                      // 今日 locked: true
      "why": "一句话说为什么推荐（用老板的话）",
      "uses": ["客户 10 位", "沟通记录 46 条"],                 // 用到老板的哪些资料
      "needs": "缺什么资料（lacking / later 时写）",
      "preview": { "kind": "clients", "...": "按 kind 填数据，见下" }
    }
  ],
  "themes": [ { "id": "jade", "name": "松石", "fit": "……", "recommended": true, "palette": { "...": "见例子" } } ],
  "schedule": {
    "boot": { "question": "你的电脑一般几点开着？", "hint": "……", "options": [{ "id": "early", "label": "早上 8 点前就开了" }], "default": "early" },
    "view": { "question": "你想几点看到今天的汇总？", "options": [{ "id": "0830", "label": "8:30" }], "default": "0830" }
  },
  "auto": [ { "label": "导航", "value": "……" } ]             // 我们替老板定好的，只展示
}
```

`profile` 每项可以多一个 `demo_fix`（可选，只给演示截图用）：用 `?step=0&edit=<id>` 打开页面时，页面把它当成老板改后的文字，演示“改一下”（改后的那段标出来，下面一行灰色小字划掉改前的说法）。Skill 正式写推荐时不用写这个字段；老板自己点“改一下”输入的文字照常进 `result.json` 的 `profile_fixes`，改前改后也按同样的样子显示。

`boot` 的选项 id 固定为 `early`（8 点前）、`nine`（9 点左右）、`late`（10 点以后）、`random`（不一定）；`view` 的选项 id 固定为 `boot`（一开电脑）、`0830`、`0900`、`1130`。页面按这两个算出建议时间。

### 预览数据（preview.kind）

| kind | 字段 |
|---|---|
| today | date、greeting、focus{title,text}、kpis[{label,value,unit,note,tone}]、agenda[{time,title,meta}]、todos[{title,due,tone}]、contacts[{name,note,when}] |
| tasks | week[{day,items[],today}]、todos[{title,due,tag,tone}] |
| clients | stages[{name,items[{name,meta,when,tone}]}]、detail{name,contact,facts[[键,值]],timeline[{date,text}],care} |
| projects | items[{name,due,progress,next,steps[],at}] |
| biz | kpis[{label,value,note,tone}]、bars[数字]、platforms[{name,gmv,delta,down,warn}] |
| content | topics[文字]、phone{cover,title,text,tags} |
| kb | tree[{name,count,note,on}]（`on: true` 的那一行高亮，和 doc 对应）、doc{title,lines[]} |
| list | title、items[{title,meta}] |
| empty | title、text |

`tone` 只用 `warn`、`danger`、`info`、`muted`。所有数据都用老板自己的真实资料；资料里没有的就少放几条，不要编。

`sources` 写文件路径，从知识库根目录写起，用 `/` 分隔（Windows 上也一样）。

确认页启动时会检查：文件是不是合格的 JSON、有没有 `boss`、`profile`、`modules`、`themes`、`schedule`（含 `boot` 和 `view`）。不合格会直接报错并说缺什么。

## result.json

```jsonc
{
  "status": "confirmed",
  "confirmed_at": "2026-10-27T07:12:30.000Z",
  "boss": { "call": "林总", "business": "ABC茶社" },
  "profile_fixes": [ { "id": "people", "title": "你在跟的人", "text": "老板改后的整段文字" } ],
  "extra": "老板在第一步补充的话",
  "wants": ["昨天各平台卖得怎么样"],
  "modules": [ { "id": "today", "name": "今日", "status": "recommended" } ],
  "custom_request": "老板说还想要的",
  "theme": "jade",
  "schedule": { "boot": "early", "view": "0830", "prepare_at": "8:15", "notify_at": "8:30", "plan": "每天 8:30 提醒你看" },
  "auto": [ { "label": "导航", "value": "……" } ],
  "saved_at": "……"                                          // 服务写入时间
}
```

`prepare_at`、`notify_at` 为空表示“开机后自动整理、整理好就提醒”。

每次重新打开确认页，上一次的 `result.json` 会先改名成 `result-上次-<时间>.json`，所以 `result.json` 一出现就是这一次的确认。页面交不上去时，会把同样内容的一段 JSON 给老板复制回对话，直接存成 `result.json` 就行（补上 `saved_at`）。
