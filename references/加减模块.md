# 加模块、减模块、改功能

工作台搭好以后，老板会不断冒出新需求。这个 Skill 让每次改动都可控：先把业务想清楚（立项对焦 → 需求文档）→ 选起点 → 看样子 → 再动手 → 验收 → 留记录。

**路径约定**：下文的 `工作台/` 指工作台所在的位置。知识库在 iCloud、网盘里时，程序和数据库在库外（例如 `~/老板工作台/<店名>/`），以 `工作台/README.md` 里写的为准。空白版在 `~/老板工作台/<名字>/`（Windows 是 `%USERPROFILE%\老板工作台\<名字>\`），下文的 `工作台/` 就是这个文件夹。下面提到的参考文件和这份在同一个 `references/` 文件夹。

## 第 0 步：先看现在的工作台

读 `工作台/README.md`：地址、程序在哪、已有哪些模块、改动记录、老板的补充、“以后想加”。没有这份文件，说明工作台还没搭，先按 SKILL.md 搭工作台。

## 第 1 步：分大小

| 老板要的 | 怎么做 |
|---|---|
| 小改动：改文字、挪位置、加一个字段、换个默认排序 | 复述一句“要改什么、什么不动”，老板点头就改，跳到第 5 步；改完给老板看前后对比 |
| 打开或收起一个已有模块 | 用模块开关，见下面“打开、收起模块” |
| 新做一块业务，或者大改一个模块 | 第 2 步立项对焦 |

## 第 2 步：立项对焦，写需求文档

按 [立项对焦.md](立项对焦.md) 和老板对焦，写成需求文档（格式见 [模块需求文档模板.md](模块需求文档模板.md)），放在 `工作台/模块需求/<日期>-<模块名>.md`。老板带着现成的需求说明来的，先读它，只补缺的。老板说“确认”再往下做。

数据来源按 [数据来源.md](数据来源.md) 的顺序选：已有数据 → 导入文件（AI 对字段）→ 飞书多维表格 → RSS → 开放平台接口 / MCP；RPA、爬虫不在这里做。

## 第 3 步：选起点

拿需求文档和模板里的参考实现比一比（三份案例需求文档的第 12 节写了参考实现在哪）：

| 情况 | 起点 |
|---|---|
| 和某个案例很像（例：老板的大客户也是线索 → 报价 → 成交 → 售后 → 复购） | 先打开那个模块（`modules --on clients`），再按需求文档改：状态名、字段、页面名、提醒规则都换成老板的；案例有、老板不要的收起来或删掉入口 |
| 只像一部分（例：要管达人合作，流程像客户跟进，对象是达人） | 新做一个模块，照参考实现的做法写：表怎么建、命令怎么写、看板和抽屉怎么做 |
| 都不像 | 新做 |

把选了哪个起点、为什么，写进需求文档第 12 节。

## 第 4 步：样张

先在工作台里做一个只读样张页（用示例数据或老板的真实数据），打开给老板看：“大概是这个样子，哪里要改？”老板点头再开发。小改动（改文字、挪位置）可以跳过样张，直接改完给老板看前后对比。

## 第 5 步：开发

- 先读工作台程序文件夹里的 `规范/README.md` 和它链接的几篇；只用规范里的组件和设计令牌，网页里不用宋体。
- 改动范围只在：`src/features/<模块>/`、`server/` 里这个模块自己的文件、新编号的迁移文件、`src/app/nav.ts` 里加一个入口（写上 `section`：放进今日 / 客户 / 经营 / 内容 / 资料哪个分区；页面多就用 `sub` 分组或 `children` 列子页面，规则见模板的 `规范/导航与Tab.md`）。要动公共文件，先说明为什么。
- 详情用右侧抽屉（地址栏参数），新建用弹窗，页内视图用 ViewTabs，看板卡片不放改状态的下拉（拖动或抽屉里改）。
- 网页和 Codex 走同一套业务规则：新增数据都加对应的命令行命令（`server/cli.ts`），不直接写 SQL。
- 新模块要能开关：在 `shared/modules.ts` 的 `MODULES` 里登记 id 和名字；`nav.ts` 里这个模块的每一项写上 `module: '<id>'`（外壳经 `src/app/nav-sections.ts` 的 `useNav()` 按开关过滤，关掉后菜单、底栏、搜索里都不出现；`npm test` 会查每一项的 `module` 都登记过）；`src/app/router.tsx` 里它的页面用 `gate('<id>', <页面 />)` 包住；要上今日页的卡片，先看 `overview.modules` 里有没有它。
- 外壳不动，只往里挂：新模块的“新建”项加进 `src/app/shell-parts.tsx` 的 `QUICK`（写上 `module`，模块关了就不出现；弹窗接到 `src/app/Overlays.tsx`），要进全局搜索就在 `server/services/today.ts` 的 `search()` 加一段（同样按模块开关判断）。今日页的重点卡在 `shared/home.ts` 登记。不另写入口页、不换 `main.tsx` / `router.tsx` 的外壳、不把模板的接口整批关掉；做完跑 `npm run doctor`，“外壳完整”才算过。
- 让 AI 助手也会用：新模块的读写加进命令行 `server/cli.ts`，再把命令名加进 `server/assistant/mcp.ts` 的 `READ_COMMANDS` 或 `WRITE_COMMANDS`（报价、收款这类要先问老板的，在 `runner.ts` 的提示词里写清）。
- 改的是参考实现（比如客户跟进的阶段、字段）：先看需求文档第 12 节写的“哪些照用、哪些要改”，改动只落在这个模块自己的文件里。
- 改前备份：在程序文件夹里运行 `node server/cli.ts backup`，数据库存成数据库旁边的 `备份/workbench-<日期>T<时分秒>.db`（默认 `工作台/数据/备份/`）；工作台往知识库里写之前，也会把原文件存到同一个 `备份/知识库/`。备份跟着数据库走：知识库在云盘里时程序和数据库在库外，备份也在库外，不会被同步上去。不放程序文件夹（重新复制模板、升级程序时碰不到它，分享程序时也不会带上老板的数据），也不放 `工作台/快照/`（那里是工作台导出给别的对话读的）。改坏了要回去：停掉工作台，把现在的 `workbench.db`（连同旁边的 `-wal`、`-shm`）挪开，把备份复制回来改名成 `workbench.db`，再启动。

## 第 6 步：验收

- 在程序文件夹里跑 `npm run build` 和 `npm run doctor`，都通过。
- 按需求文档第 11 节“怎么算好”逐条检查，截图给老板看；小改动按第 1 步复述的那句话检查。
- 告诉老板：改了什么、怎么用、没做什么（需求文档里“以后再说”的那些）。

## 第 7 步：留记录

- 在 `工作台/README.md` 的“改动记录”里加一行：日期、需求文档路径（小改动写那句话）、改了哪些文件、怎么回退。
- 需求文档末尾加一行“已上线（日期）”；上线后老板又改了主意，改需求文档、版本加一，再按第 3 步往下做。

## 打开、收起模块

老板说“这个模块用不上了”“导航太多了”“把经营打开”：用模块开关，不改代码、不删数据。

1. 先确认是哪个；收起时告诉老板“代码和数据都留着，只是从导航、今日页和提醒里收起来，想用随时打开”。
2. 在程序文件夹里运行（程序在库外时照样带 `WORKBENCH_ROOT`、`WORKBENCH_DB`）：

   ```bash
   node server/cli.ts modules                 # 看每个模块开没开
   node server/cli.ts modules --off biz       # 收起
   node server/cli.ts modules --on content    # 打开（经营、内容会自动带上数据源与导入）
   ```

   老板也可以自己在网页“设置 → 模块”里开关。今日、设置一定开着；还有别的模块要用的（比如数据源与导入），先关用它的那个。
3. 打开首页给老板看；在 `工作台/README.md` 的模块清单里标“已收起（日期）”或“已打开（日期）”，“改动记录”加一行。

导航里的顺序、分区要换：只改 `src/app/nav.ts`（规则见模板的 `规范/导航与Tab.md`），`npm run build` 通过后给老板看。

## 案例和参考实现

三个业务模块在模板里有现成的参考实现，默认可以收着，学员按自己的需求文档打开、改造或照着新做。案例需求文档是“写好的需求长什么样”，不是让老板照着选的答案。

| 案例需求文档 | 讲什么 | 参考实现（模块 id） |
|---|---|---|
| [需求文档-客户跟进.md](需求文档-客户跟进.md) | 大客户从线索、报价、成交、交付售后到复购和长期合作；谁跟到哪了、卡在谁那里 | `clients` |
| [需求文档-多平台经营.md](需求文档-多平台经营.md) | 汇总页 + 每个平台一页、数据新鲜度、异常从发现到处理、AI 日报 | `biz`（自动带上 `data`） |
| [需求文档-小红书内容中心.md](需求文档-小红书内容中心.md) | 一篇笔记从选题到复盘；创作页和 AI 对话；发布前检查；每周复盘。写作规则见 [配方-小红书内容中心-写作规则.md](配方-小红书内容中心-写作规则.md) | `content`（自动带上 `data`） |
| [配方-数据导入与对字段.md](配方-数据导入与对字段.md) | 老板自己的导出表，AI 认字段、存成导入规则 | `data` |

| [需求文档-报价到回款.md](需求文档-报价到回款.md) | B2B 一单生意从询价到尾款：卡在技术、合同、首款还是验收；报价、合同、到账、待收分开（虚构） | 照客户跟进的看板和应收款新做（`deals`） |
| [需求文档-项目交付与验收.md](需求文档-项目交付与验收.md) | 专业服务按项目交付：场次带分母、交付物、验收凭据（虚构） | 在基础版项目上加（`delivery`） |

五种行业的工作台各长什么样（首页、导航、加什么），看 [行业样板.md](行业样板.md)。

## 规矩

- 不编数据：老板没给的数字不填；示例数据只在演示模式。
- 客户承诺、报价、成交、回款，写入前给老板确认。
- 知识库原文不改；模块需要的知识（方法、话术、口径）从知识库读，缺了提示用 boss-kb 补。
- 模块要往知识库写，只做三种写：客户或项目文件的“往来记录”末尾追加一条（写明 `来源: 工作台`）（就地建图的库：老板原有的文件不追加，写进同一文件夹的 `<客户名或项目名>-往来记录.md`，类型 往来记录）；新材料放进 `00-收件箱/`；在 `90-持续生长/待确认的发现.md` 追加一条发现。别的改动先提议，老板确认后交给 boss-kb 写。
- 外部数据的账号、密钥只放本机环境变量或系统钥匙串，不写进文件、不进截图。
