# 助理用内容工作台（小红书）

小红书助理（或别的写内容的助理）写的选题和稿子，存进工作台的小红书内容中心：老板在“小红书 → 内容 / 创作”里看得到、接着改，助理页的“产出”里也按助理列出来（约定 11.13）。这一页是给引导工具和助理看的命令说明；命令以后变了只改这一页。要装了小红书模块（“工作台装上小红书模块”）。

## 规矩

- 每条写入命令都带 `--by <助理名字>`（就写名字，比如 `--by 阿柚`），工作台按它把产出记到这位助理头上。不带的记成 Codex，助理页认不出。
- 在程序文件夹里跑：`node server/cli.ts <命令> …`；要读结果就加 `--json`。程序放在知识库外面的，照工作台的说明带上 `WORKBENCH_ROOT`、`WORKBENCH_DB`。
- 一篇从选题到发布是同一条，编号形如 `p_1a2b3c4d`；改稿、放图都存成新的一版，旧版留着，老板能在“版本”里恢复。
- 对话里只回标题、一句说明、放在哪、怎么打开，正文和图不贴回对话。

## 每个动作用哪条

| 要做的 | 命令 | 回什么 |
|---|---|---|
| 看有哪些账号 | `xhs-accounts --json` | 每个账号的名字、定位、写给谁看、人设、风格、不碰的东西、知识库文件 |
| 登记或改一个账号 | `xhs-account-save --name 账号名 [--handle 小红书号] [--positioning 定位] [--audience 写给谁看] [--persona 人设] [--style 风格] [--avoid "甲、乙"] --by 阿柚` | 写进知识库的文件路径；只改给了的几项，正文不动。写之前先跟老板说清要登记什么 |
| 存一个选题 | `xhs-topic-add --title "标题" [--angle "切入角度"] [--reason "一句说明"] [--account 账号] --by 阿柚` | 编号（`id`）；同名的不重复存，回已有那篇（`existed: true`） |
| 在选题下存稿 | `xhs-draft-save --id <编号> --file 稿件.json --by 阿柚`（或 `--draft '<JSON>'`） | 编号、第几版、知识库里的作品文件 |
| 没有选题直接存稿 | `xhs-draft-save --file 稿件.json --by 阿柚`（不带 `--id`，自动建一篇） | 同上 |
| 改稿，存成新的一版 | 同一条，带上那篇的 `--id` | 第几版 |
| 把图放进某一篇 | `xhs-image-add --id <编号> --from-codex [--page 0] --by 阿柚`（刚用 image_gen 生成的那张），或 `--file <图片路径>` | 放在哪（封面 / 第几张内页）、第几版、用的是哪个文件 |
| 列出、找到某一篇 | `xhs-pieces [--q 关键词] [--status 选题\|草稿\|定稿\|已发布] [--by 阿柚] [--account 账号] --json` | 每篇的编号、账号、标题、阶段、第几版、谁做的、网页地址；最近动过的在前，最多 30 条 |
| 打开给老板看 | `workbench_open`，kind 写 `xhs-piece`，id 写编号 | 地址（在 Codex 右边打开）；命令行的结果里也有 `path`：`/content/studio/<编号>` |

稿件 JSON 写这几项：`title`（标题）、`summary`（一句说明）、`cover_text`（封面大字，用“｜”分两行）、`pages`（每张图上的字，第一张是封面）、`body`（正文）、`tags`（话题，不带 #）、`sources`（用到的知识库文件，如 `1-老板说明书/老板说明书.md`）。标题和正文必填。

放图：`--page 0` 是封面（默认），`1`、`2`…… 是第几张内页（不能超过 pages 里的内页数）。只收 png、jpg、webp、gif，20MB 以内；图复制一份进工作台数据文件夹旁边的 `小红书素材/`（文件名是素材编号），原图不动。没放图的封面显示“实拍图位置（占位）”。

## 配图：用 Codex 的生图工具

- 工具：Codex 自带的 `image_gen`（功能开关 `image_generation`，默认开；Codex 里还有一个同名的系统技能 imagegen 讲怎么用）。不用另外的 API key。生成的图存在 `$CODEX_HOME/generated_images/<对话编号>/`（默认 `~/.codex/generated_images/`），PNG。
- 生成以后直接 `xhs-image-add --id <编号> --from-codex --page 0 --by <名字>`：取两小时内 Codex 最新生成的那张放进去，结果里写着用的哪个文件。要放更早的或别处的图，用 `--file`。
- 比例：竖版 **3:4**（推荐 1080×1440 或更大，比如 image_gen 出的 1086×1448）。工具没有尺寸参数，在提示里写“竖版、高比宽长、接近 3:4”。一篇里所有图用同一个比例。
- 封面：画面上方留出三分之一干净的浅色区域，标题大字由工作台的封面模板压上去，**图里不要放字**；封面大字不超过 12 个字（工作台发布前检查按这个查），用“｜”分两行。
- 不用真实品牌、真人脸；店里的东西没有实拍时，生成的是示意图，发之前换实拍或让老板确认。
- 出处：比例 3:4 / 1:1 / 4:3、一篇只用一种比例、后面的图按第一张裁，**没查到小红书官方页面**，来自第三方整理（Canva 中国的小红书封面指南、人人都是产品经理的笔记配图规范），工作台的手机预览也按 3:4 画；一篇最多 18 张图出自小红书官方小工具文档（发布笔记接口图片 1—18 张）。平台规则以发布页的提示为准，变了改这一节。

## 账号

- 账号以知识库为准：一个账号一份文件，默认在“关于我”文件夹下的 `小红书账号/`（知识库档案“位置”表登记了“小红书账号”就放那）。开头写：名称、小红书号、定位、写给谁看、人设、风格、不碰（列表）；正文老板随便写（怎么拍、常用开头……）。工作台只读这份，不另存。
- 选题、稿子、图都挂在账号下：只有一个账号时不用写 `--account`；有两个以上的，`xhs-topic-add`、`xhs-draft-save` 新建时要写是哪个。
- 写稿前先 `xhs-accounts` 读账号的定位、写给谁看、人设、风格、不碰的东西，照着写。
- 还没有账号时（助理刚上岗）：问老板有没有小红书账号、叫什么、写给谁看、想要什么人设和风格、哪些不碰；说清要登记什么，他点头再 `xhs-account-save`。老板不想聊也可以先写，之后再补。

阶段的说法：选题（灵感池、已选）→ 草稿（写稿中）→ 定稿（待发布）→ 已发布。定稿、发布由老板在内容页里点，助理不改。

## 一个来回的例子

```bash
node server/cli.ts xhs-topic-add --title "行政别慌，送客户的圣诞礼盒这样选" --angle "对着公司行政写：198 和 398 两档各送给谁" --by 阿柚 --json
# → {"id":"p_f9474838", …, "path":"/content/studio/p_f9474838"}
node server/cli.ts xhs-draft-save --id p_f9474838 --file 稿件.json --by 阿柚
# 在 Codex 里用 image_gen 生成一张竖版 3:4 的封面底图，然后：
node server/cli.ts xhs-image-add --id p_f9474838 --from-codex --page 0 --by 阿柚
node server/cli.ts xhs-pieces --by 阿柚
```

然后对老板说：“写好了，存成草稿了。标题……一句话……放在工作台内容页。”并用 `workbench_open`（xhs-piece，p_f9474838）在右边打开。

## 写进“会用的家伙”的要点（给引导工具）

- 写稿、存选题用工作台的小红书内容中心，命令见 Skill 的 `references/助理用内容工作台.md`；每条带 `--by <自己的名字>`。
- 刚上岗先 `xhs-accounts` 看有没有登记账号；没有就问老板账号名、写给谁看、人设、风格、不碰的东西，点头后 `xhs-account-save` 登记。
- 配图用 Codex 的 `image_gen`，竖版 3:4、图里不放字、上方留白给标题；生成后 `xhs-image-add --id <编号> --from-codex --page 0` 放进封面。
- 先 `xhs-pieces --by <名字>` 看自己手上有哪几篇，接着改的带 `--id`。
- 存完用 `workbench_open`（kind `xhs-piece`）给老板打开那一篇；对话里只说标题、一句话、放在哪。
- 没装小红书模块时：稿子按知识库的规矩存进作品文件夹，并告诉老板说一句“工作台装上小红书模块”就能在工作台里看、接着改。
