# 进内容：先拆、再问、一张清单、一次写入

老板丢进来一段聊天、一份会议纪要，或者说“和某某聊了”“定了”“这几件事记一下”：不要只记一条原文，也不要只回一句“去工作台加个待办”。先拆清楚，把要老板定的在对话里一次问清，列一张清单，老板说“确认”后一次写进工作台（有知识库的，知识库那边按老板知识库 Skill 的 `references/进内容.md` 写）。

## 六步

1. **认出来**：是什么、哪天、谁在场、说的是哪位客户或哪个项目。对不上就问，不猜。
2. **拆成 7 类**：

   | 类 | 拆什么 | 写进工作台的哪里 |
   |---|---|---|
   | 状态变化 | 客户阶段、项目进度、卡在哪、在等谁 | 客户阶段 `stage`（要写原因）；项目 `project-set --stage --waiting` |
   | 决定 | 定了什么、谁定的（老板亲口说的、别人提的、AI 推断的），带原话出处 | 往来记录里写清；项目的写进项目下一步或备注；知识库的“关键决策”交给知识库 Skill |
   | 下一步 | 新的下一步；替代了哪条旧的 | 客户 `follow <客户> <日期> --step`；项目 `project-set --step` |
   | 待办 | 做什么、谁做（老板、团队里谁、对方）、哪天前；“周四前”换成日期 | `todo-add --owner 谁 --due 日期 --source 材料`；在等对方的写 `--owner 对方 --status 等别人` |
   | 里程碑和日期 | 上线、交付、付款节点、活动日 | `milestone-add <项目> "日期 做什么"`；要到点提醒的再加日程 |
   | 要老板拍板的 | 还没人定、又必须老板定的事 | 先在对话里问；问不到的放收件箱，带判断和默认建议 |
   | 答应、顾虑和信号 | 我们答应了什么（给谁、什么、哪天前）；对方担心什么；买不买的信号 | 答应的事 `promise-add`，同时建一条待办；顾虑写进往来记录 |

   “考虑一下”“再看看”不算决定，阶段不往前走。报价、价格、交期、补偿、签约、回款、对外承诺，在清单里单独列出，老板确认才写。
3. **先问**：缺的、拿不准的合成一次问，最多 3 个问题，每个给默认（例：“两套方案小周做、10/30 前给你看？（是）”）。先问会改结果的：谁做、哪天前、算不算定了。
4. **一张清单**：拆的结果、要问的、要写的，列成一张。老板说“确认”就全写，说“写 1、3”就只写这几条。
5. **一次写入**：把确认的内容写成清单文件，先预演，再写：

   ```bash
   node server/cli.ts apply "<清单.json>"          # 预演：照样检查，什么都不留
   node server/cli.ts apply "<清单.json>" --yes    # 老板确认过：一次写入；中间哪步不行，整张都不写
   ```

   清单格式见工作台程序里 `server/services/apply.ts` 开头。能写的有：
   - 往来记录（`log`）、待办（`todo`，带 `owner` 谁做）、改待办（`todo-set`）；
   - 答应的事（`promise`）、改阶段（`stage`，要写原因）、下次跟进（`follow`）；
   - 改项目（`project`）、里程碑（`milestone`）、日程（`event`）、收件箱处理完（`inbox-done`）。

   只有一两条时，直接用对应的单条命令也行。程序在知识库外面时，命令照样带 `WORKBENCH_ROOT`、`WORKBENCH_DB`，见 `工作台/README.md`。
6. **汇报**：一句话说清写了哪几处、建了哪几条待办（谁做、哪天）、还有哪几个问题等老板回答。

## 收件箱放什么

收件箱只放三种：老板随手记的、还没想清楚的材料、没人对话时后台进来的（定时任务、导入）。AI 放进去的每一条都要带判断：

```bash
node server/cli.ts inbox "澜拓微信：问春节能不能加印 logo" --kind 材料 \
  --why "在问加印 logo，涉及报价" --suggest "列进澜拓的清单，问老板收不收费（默认 50 份以上免费）" \
  --client 澜拓科技 --from "00-收件箱/2026-10-28-澜拓-微信.md"
```

不往收件箱倒原文。处理完用 `inbox-done <ID> --result "处理成什么了"` 标掉。

## 老板不在对话里时

定时任务、后台导入时没人可问：照样拆；不建待办、不改阶段和状态；要建的待办、要拍板的事，用 `inbox --kind 后台 --why --suggest` 各放一条，或者写进这次的报告“等你回答”，每条带判断和默认建议。老板下次说“整理收件箱”时，照六步走。

## 网页上的“新材料提取”

客户与跟进模块里的“新材料提取”是网页版的同一件事：AI 提取答应、顾虑、下一步，老板在网页上点“确认写入”。在 Codex 对话里，用上面的六步和 `apply`，问完老板直接写，不用再去网页点。
