# 模块需求文档：项目交付与验收

> 一句话：给做用户研究的周岚用，把每个委托项目从“范围确认”管到“客户验收、结项”；打开就知道每个项目做到第几场、交了什么、客户认没认。
> 状态：课上范例（按五轮模拟里虚构的“折页用户研究”写，人和事全部虚构）｜版本：v1
> 适合：咨询、设计、研究、培训、律所这类按项目交付的专业服务。和基础版“项目”的区别：多了场次进度、交付物和验收。

## 1. 为什么要做

结论：项目进度、交付物和客户反馈散在项目手记、范围确认和访谈摘记里，最容易把“做完了”“交出去了”“客户认了”混成一回事。

- 现在怎么做：每个项目一份手记，范围确认单一份，访谈和测试摘记一堆。
- 卡在哪：
  1. 场次进度只记了“做了 7 场”，忘了分母是 8。
  2. 交付了等客户反馈，过了几天没人跟。
  3. “项目结束”和“客户验收”没分开，没有验收凭据。
- 做完以后：打开项目，看到每类场次几场 / 共几场、交付物交了哪几份、客户验收了没（凭什么）。

## 2. 谁在什么时候用

| 场景 | 谁 | 什么时候 | 想知道或想做什么 |
|---|---|---|---|
| 看项目进度 | 周岚 | 每天 | 哪个项目快到汇报日、场次够不够 |
| 记一场 | 研究员 | 每场访谈 / 测试后 | 记一场，进度自动加一 |
| 交付后跟反馈 | 周岚、项目负责人 | 交付后 | 谁哪天跟客户要反馈 |
| 结项 | 周岚 | 客户确认后 | 记验收凭据，项目结项 |

## 3. 业务流程

范围确认 → 招募 → 访谈 / 测试（按场次）→ 分析 → 交付（报告、汇报）→ 等客户反馈 → 客户验收 → 结项。

例外：客户提前要口头结论（记成一次“中途汇报”，不算交付）；范围变了先改范围确认，再改场次分母。

## 4. 关键对象和状态

| 东西 | 要记哪些信息 |
|---|---|
| 项目 | 客户、负责人、范围（几类场次、各几场）、内部目标日、客户约定日 |
| 场次 | 类型（访谈 / 测试）、日期、受访者编号（不记真名）、摘记链接 |
| 交付物 | 名称、交付日、交给谁、客户反馈 |
| 验收 | 日期、凭据（邮件、签字、口头确认写清谁说的） |

| 状态 | 进来的条件 | 下一步 |
|---|---|---|
| 进行中 | 范围确认了 | 场次做完 → 分析 |
| 已交付 | 交付物发出 | 跟反馈 |
| 等反馈 | 交了还没回音 | 客户确认 → 已验收 |
| 已验收 | 有验收凭据 | 结项 |
| 已结项 | 收尾完成 | — |

规矩：场次一定带分母（7/8，不写 88%）；场次完成不等于结论可靠；“已结束”不等于“已验收”，没有凭据就写“验收未知”。

## 5. 页面和交互

放在“今日”分区的“项目”里（扩展基础版项目页，不另开菜单）。

| 页面 | 第一屏看到什么 | 能做什么 |
|---|---|---|
| 项目列表 | 每个项目：状态、场次进度条（带分母）、下一个关键日 | 筛“等反馈” |
| 项目详情 | 范围、场次列表、交付物、验收记录、往来 | 记一场、记交付、记验收 |

## 6. AI 帮什么

| AI 做什么 | 结果写到哪 | 要确认吗 |
|---|---|---|
| 从访谈摘记里登记一场 | 场次 | 不用（普通进展） |
| 交付后第 3 天提醒跟反馈 | 待办 | 待办先给周岚看 |
| 记验收 | 验收 | **要**：没有凭据不记 |

## 7. 提醒

内部目标日前 3 天；交付后 3 天还没反馈。

## 8. 数据从哪来、存在哪

项目、场次、交付物存工作台数据库；摘记原文留在知识库，场次只存链接。受访者真名、联系方式不进工作台（受访者材料按她的边界只放编号）。

## 9. 规矩和边界

- 不替周岚对客户说结论；不把内部目标日写成客户约定日。
- 受访者匿名：只记编号。

## 10. 第一版做什么

- 一定要有：场次进度（带分母）、交付物、验收记录。
- 以后再说：工时、按项目算收入。

## 11. 怎么算好

- [ ] 打开项目 10 秒内说出“访谈几场 / 共几场、交了什么、客户认没认”
- [ ] 结束但没验收凭据的项目，显示“验收未知”
- [ ] 手机宽度能看；`npm run build`、`npm run doctor` 通过

## 12. 给开发的提示

- 参考实现：基础版项目（`src/features/projects`，里程碑已经有）。在项目详情里加“场次”“交付物”“验收”三块。
- 模块开关 id：`delivery`；需要 `projects`。
- 表：`project_sessions`、`project_deliverables`、`project_acceptance`。
- 命令行：`session-add`、`deliverable-add`、`accept <项目> --proof`（验收在 AI 助手提示词里写清先问）。
