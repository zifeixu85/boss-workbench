# 配方：数据导入与对字段

每个老板的数据都在不同平台，导出来的表叫法不一样。这个模块让老板把导出表拖进来，AI 第一次对好字段、老板确认，存成规则，以后同一种表直接导。

## 三行需求（示例）
- 要什么：一个“数据源”页看每个来源新不新；一个“导入”页，拖进表格，AI 认出是哪个平台、列出字段对照，我确认后导入；以后同一种表放进文件夹就自动导。
- 什么不能动：已经导入的数据；平台上的任何东西。
- 怎么算好：把天猫、抖店两份导出表拖进去，3 分钟内经营页有数；表格格式变了会提醒，不会悄悄算成 0。

## 页面

| 页面 | 放什么 |
|---|---|
| 数据源 | 每个来源一行：名称、方式（导入文件 / 飞书多维表格 / RSS / 定时任务 / 本地文件）、送来什么、最近更新、状态（正常 / 没按时更新 / 读取失败）、下一次；点开抽屉看每次运行记录；“立即同步” |
| 导入 | 第 1 步拖文件（CSV、Excel）；第 2 步 AI 对字段：认出平台和报表类型，对照表（源列 → 工作台字段、示例值、把握：已对上 / 拿不准 / 用不上），拿不准的标黄，可下拉改；单位和日期格式；第 3 步预览前 10 行和将写入的数量；第 4 步导入完成：行数、日期范围、去经营页看 |
| 导入规则 | 每条规则：平台、报表、表头特征、字段对照、单位、最近一次用；可以改、停用 |
| 导入记录 | 每次导入：文件名、规则、行数、日期范围、结果；失败的写清原因（例：缺“推广花费”列） |

## 对字段怎么做
1. 读表头和前 20 行；按表头特征判断平台和报表（例：有“支付金额”“支付买家数”多半是天猫生意参谋；有“成交金额”“千川消耗”多半是抖店）。
2. 先用常见叫法对照表自动对上能确定的；对不上的、可能有两种意思的（例：“成交金额”含不含退款）标“拿不准”，请老板选。
3. 单位：元 / 万元 / 百分比；日期：2026/10/26、20261026、10月26日都认。
4. 老板确认后存规则到 `工作台/导入规则/<平台>-<报表>.json`。
5. 同一份数据重复导入按“日期 + 渠道”覆盖，不重复累加。
6. 以后放进 `工作台/数据导入/` 的表，按规则自动导；表头对不上就停下来提醒。

在 Codex 里也能做同样的事：“把这份抖店导出表导进工作台”——Codex 按上面的步骤读表、列对照、等老板确认、用工作台命令导入。

## 常见叫法对照（节选）
| 工作台字段 | 常见叫法 |
|---|---|
| 成交额 | 支付金额、成交金额、GMV、实收金额、营业额 |
| 订单数 | 支付订单数、成交订单数、支付子订单数、单数 |
| 访客数 | 访客数、商品访客数、进店人数、UV |
| 退款金额 | 退款金额、成功退款金额、售后退款 |
| 推广花费 | 推广花费、千川消耗、直通车花费、广告消耗、投流花费 |
| 推广成交额 | 推广成交、直接成交金额、广告成交 |

## 演示怎么做
准备两三份不同平台的导出表（老板自己的；没有就自己造几份列名各不一样的样例表，标明是示例）。先拖一份，看 AI 认平台、对字段，拿不准的标黄等你选；再拖一份故意删掉“推广花费”列的，看它停下来提醒，不悄悄算成 0。

## 两条硬要求（借鉴）
- 导入前先预览：成功多少条、哪几条有问题（行号 + 原因）；导入后能一键撤销这一次导入。
- 示例数据和老板自己的数据分开标记，示例能一键清掉；示例数据要像真用过一段时间，前后对得上。
