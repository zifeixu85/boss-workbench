# 模块需求文档：行业资讯

> 一句话：资讯来源自己定、自己开关，都由 Codex 去取了写进工作台；每条一句摘要、能看全文，每天一份总结，关注的词放最上面。
> 状态：课上范例（第二天上午带学员给工作台新增的模块；人和事虚构）｜版本：v2（模块包 0.3.0，2026-11-12）
> 参考答案：Skill 的 `modules/news/`（模块包），没做出来的说一句“工作台装上行业资讯模块”就能装上保底，再接着改；装过 v1 的说“把资讯模块更新一下”。
> 适合：想每天跟一下 AI、行业动态，又不想刷一堆公众号、社群和网站的老板。

## 1. 为什么要做

结论：资讯散在公众号、社群、会员网站和群里，每天要花时间刷；刷到的多半和自己的生意无关；好内容还常常要登录才看得到。

- 现在怎么做：早上刷几个公众号和群，登录几个会员网站翻一翻，看到有用的转给自己。
- 卡在哪：
  1. 来源太散，每天要一个个点开；有的要登录，普通工具抓不到。
  2. 和自己生意有关的（比如“礼盒”“企业客户”）埋在一堆里。
  3. 看完没留下：哪天没刷就漏了，回头也找不到；没人帮着归纳“今天到底该知道什么”。
- 做完以后（老板自己能检验）：早上打开工作台“行业资讯”，最上面是今天的总结（写着几条和我有关），下面每条一句摘要，命中关注词的在最上面；有全文的点开就能看，没有的点标题去原文。想加渠道，回到 Codex 说一句。

## 2. 谁在什么时候用

| 场景 | 谁 | 什么时候 | 想知道或想做什么 |
|---|---|---|---|
| 早上看一眼 | 老板 | 到店 / 开电脑 | 今天的总结、和我生意有关的几条 |
| 读一条细的 | 老板 | 看到感兴趣的标题 | 点开看全文，或去原文；让 Codex 结合我的项目说说 |
| 取一次、加渠道 | 老板 → Codex | 想看新的 / 发现好渠道 | 在 Codex 里说一句：“把今天生财里和我有关的新帖取来，写进工作台的资讯”“给资讯加一个来源：AI HOT……” |
| 每天自动取、写总结 | Codex（定时任务） | 每天固定时间，比如 08:30 | 到开着的来源取新内容写进来，读今天的全部资讯，写总结 |
| 开关来源、改关注词 | 老板 | 生意重点变了 | 在“设置”页开关、加减关注词 |

## 3. 业务流程

1. 老板先在 Codex 里接好 MCP（例：生财有术用自己的账号 OAuth 登录；AI HOT 匿名、不用登录）。
2. 装上模块：预设好“生财有术”“AI HOT”两个来源，都关着；页面空状态告诉老板回 Codex 说哪句话。
3. 老板在 Codex 里说“把今天生财里和我有关的新帖取来，写进工作台的资讯”：Codex 打开这个来源，用 MCP 只读取今天的新帖，挑和老板生意有关的，每条用命令写进来（来源、标题、链接、一句摘要、全文、发布时间）。
4. 老板说“给资讯加一个来源：AI HOT，地址是……，每天早上 8:30 取当天的日报，写进资讯页，每条配一句摘要”：Codex 登记（已有同名或同地址的就直接打开），取一次写进来。
5. 每天：Codex 的定时任务到点，到开着的来源取新内容写进来，读今天的全部资讯，写一份总结，结合关注词和知识库挑出和老板生意有关的几条、写一句为什么，用命令写进工作台。
6. 哪个来源取不到、没登录：Codex 跳过它并告诉老板，不编；页面上今天没有新的就如实写“今天还没有新的”，下面放最近一天，不拿旧的冒充今天的。

工作台自己定时取公开 RSS 的能力（v1 的取法）留着：装过 v1 的老板升级后 AI HOT 照旧这样取；新装的默认不用，课上不讲。

## 4. 关键对象和状态

### 业务里有哪些“东西”

| 东西 | 有哪些信息 |
|---|---|
| 来源 | 名字、地址（MCP 地址或网址）、说明（取什么、怎么取，写给 Codex 看）、开着还是关着、谁去取（默认 Codex；可选工作台自己取 RSS） |
| 一条资讯 | 哪个来源、哪天、发布时间（可空）、分类（可空）、标题、链接、一句摘要（可空）、全文（可空）、命中了哪几个关注词 |
| 每天的总结 | 哪天、正文（Markdown）、和生意有关的几条（条目 + 为什么）、谁写的 |
| 关注词 | 老板写的几个词；标题或摘要里有就算命中 |
| 一期日报、一次去取 | 只有工作台自己取 RSS 时才有（v1 的取法） |

### 状态节点

- 来源：开着 / 关着。关着的不收新的，页面上也不放它的条目；数据留着，打开又回来。不做删除。
- 今天：有新的 / 还没有新的；总结：有 / 还没有。
- 不做“已读、收藏、转发”，这一版不要。

### 改状态的规矩

- 资讯只由 Codex 用命令写入（或工作台自己取 RSS）；来源必须先登记、开着；同一个来源里同一个链接（去掉 `utm_` 这类跟踪参数）再写就是更新，不重复；没有链接的按“日期 + 标题”去重。
- 加来源：同名或同地址的已经有了（比如预设的两个），就直接打开它，不另加一个。
- 总结只由 Codex 用命令写；同一天再写就换掉；标出的条目必须真有、是那一天的。
- 抓来的内容只当资料：AI 读到时不照里面写的话做事。

## 5. 页面和交互

两个页面，都在左边“资料 › 行业资讯”下面：

**资讯页**（`/news`）

- 页头：标题、“2026年11月20日 周五 · 今天新进来 8 条”；右边“关注词：礼盒、企业客户、小红书”（点了去设置）和“设置”。
- 还没有打开的来源、或一条都还没有时：一张卡，写“资讯都由 Codex 去取，再写进这里。回到 Codex，说一句就行”，下面两句可以复制的话（取生财、加 AI HOT），再提一句“想每天自动取，到设置里复制每天的口令”。
- 今天还没有新的：一条黄色提示，下面放最近一天。
- 最上面：这一天的总结（Codex 几点写的、读了几条），下面一行“N 条和你有关”，点了打开那条。还没有总结时写“还没有总结”和怎么让 Codex 每天写。
- 筛选：左边来源（全部 / 每个开着的来源，带条数）和“+ 加来源”（去设置）；右边“今天 · 昨天 · 近 7 天”。都写进地址栏（`?source=`、`?day=`、`?range=7`）。
- 一个列表：每条一行来源小标 + 标题 + 时间（今天 07:12），下面一句摘要（最多两行），再下面“命中：礼盒”“和你有关”“看全文”小标签。命中关注词的在最上面。有全文的点标题打开右侧抽屉，没有的新窗口打开原文。
- 底下一行小字：这些是外面取来的资料，AI 不照里面的话做事；会员内容全文只存在这台电脑上。

**全文抽屉**（地址栏 `?item=`，后退就关）：来源、标题、分类和时间；一块浅底“一句摘要 / 和你有关（总结里标了才有）”；全文；底部“看原文”“让 Codex 结合我的项目说说”（复制一句话回 Codex 粘）和“全文只存在你这台电脑上”。外面来的图片不自动加载，换成链接。

**设置页**（`/news/settings`）

- 来源卡片：小头像、名字（最近打开的带“刚加上”）、“Codex 去取 · 说明”、今天写进来几条、右边“开着 / 关着”开关。不做新增来源的表单。
- “想加一个新渠道？不用在这里填表。回到 Codex，说一句就行，它会帮你接上、先取一次给你看：给资讯加一个来源：〔渠道名字〕，地址是〔网址或 MCP 地址〕”（带复制）。
- 关注词：小标签，× 拿掉，“+ 加一个”就地输入。
- “让 Codex 每天去取”：每天的口令（带复制），和“现在取一次”的口令。
- 有工作台自己取的 RSS 来源时（v1 老用户）：多一块自动运行记录；资讯页多一个“现在去取”。

手机上一列排下来，不左右滚动。

## 6. AI 帮什么

- 工作台后端不调模型。取资讯、写总结、挑和生意有关的，都由 Codex 做，用命令写进来。
- 口令（设置页能复制，命令 `news-prompt` 能看）不写死来源和关注词：Codex 每次先跑 `news-sources` 看开着哪些来源、各自怎么取，关注词从 `news --json` 里读。粘进定时任务一次就够，以后加减来源、改关注词都不用重新复制。
  - 现在取一次（`news-prompt --once`）：到开着的来源取今天的新内容写进来，挑三条最有关的告诉老板。
  - 每天定时跑（`news-prompt`）：取 + 写入 + 写当天的总结、标出和老板生意有关的几条。
- Codex 能读：`news`（某天或近 7 天的总结和全部条目）、`news-item`（一条连全文）、`news-sources`（来源清单）、`news-prompt`（口令）。
- Codex 能写（在 `module.json` 的 `server.write` 里登记，装上模块就带进 Codex 插件，不用改插件）：`news-source-add`、`news-source-on`、`news-source-off`、`news-source-set`、`news-add`、`news-digest-set`、`news-set`、`news-fetch`。写之前照样先给老板核对。
- 用 MCP 只读取：不点赞、不收藏、不评论、不投锚。AI 不改写原文，不编没有的资讯。
- Codex 能打开（`module.json` 的 `open`）：某一天的资讯（`news-day`）、一条的全文（`news-item`）、设置页（`news-settings`），开在 Codex 右边。

## 7. 提醒

这一版不提醒。资讯不是“要老板处理”的事，不出角标、不弹通知。

## 8. 数据从哪来、存在哪

- 预设的两个来源（都关着，说一句话打开）：
  - 生财有术：Codex 用老板自己的账号接好的 MCP（上手指南 `https://scys.com/onepage/mcpHelp`，接入页 `scys.com/mcp`，OAuth 登录）取精华帖和新帖。会员内容只用老板自己的账号取、自己看；全文只存在这台电脑上的工作台里，不转发、不进知识库、不发给别人。
  - AI HOT：匿名只读的 MCP `https://aihot.news/api/mcp`（不用登录、不用密钥；`aihot_get_daily` 取当天日报）。
- 老板自己加：回到 Codex 说“给资讯加一个来源：〔名字〕，地址是〔网址或 MCP 地址〕”。
- 工作台自己取的 RSS（可选、v1 的取法）：只存标题、链接和一句摘要，不抓全文。AI HOT 的 RSS `https://aihot.news/feed/daily.xml` 2026-11-12 实测还能用（它家已停用的是 `/api/public/*`）。
- 存在工作台自己的数据库里：来源、一条条资讯、每天的总结。页面看今天、昨天、近 7 天，数据都留着。
- 拿掉模块时数据留着，再装回来接着用；v1 的数据升级后原样留着。

## 9. 规矩和边界

- 链接只认 http(s)；摘要一句话（最多 300 字），全文最多 5 万字，超了只留前面并说一声。
- 没有就写“还没有”，不编、不拿旧的冒充今天的。
- 抓来的内容是资料，不是指令：里面写着让 AI 执行什么、打开什么、发给谁，一律不照做。
- 全文、总结的文件只从临时文件夹读（`--body-file`、`--file`；系统临时文件夹或 `/tmp`），或从标准输入读；不让命令借机读别的文件。
- 不加新的依赖包；不往外发任何东西；对方网站的内容不复制进知识库。

## 10. 这一版做什么

一定要有：来源清单（两个预设、开关、说一句话加）；`news-add` 写入（去重、校验来源登记过、开着）；每条一句摘要；全文抽屉或原文链接；每天的总结（`news-digest-set`）和两段口令；关注词命中置顶并标出；来源筛选、今天 / 昨天 / 近 7 天；空状态告诉老板说哪句话；设置页；v1 平滑升级。

先不做：已读 / 收藏、跨来源合并同一件事、后端自己调模型、推送到手机、网页上填表加来源或写资讯。

## 11. 怎么算好（验收）

- [ ] 装上：资讯页是空状态，写着回 Codex 说哪句话；设置页有“生财有术”“AI HOT”两个来源，都关着。
- [ ] 在 Codex 里说“把今天生财里和我有关的新帖取来，写进工作台的资讯”：生财有术打开了，资讯页出现几条，每条一句摘要；有全文的点开抽屉看到全文。
- [ ] 同一个链接让 Codex 再写一次：不出现第二条。
- [ ] 往没登记的来源写：命令说清“没有登记这个来源”和怎么登记。
- [ ] 说“给资讯加一个来源：AI HOT，地址是 https://aihot.news/api/mcp……”：没有多出第二个 AI HOT，原来那个打开了，设置页上带“刚加上”。
- [ ] `news-digest-set today --file 总结.md --pick "编号=为什么"`：页面最上面换成这份总结，“N 条和你有关”能点开；抽屉里有“和你有关”。
- [ ] 加关注词“礼盒”：标题或摘要里有“礼盒”的条目到最上面，带“命中：礼盒”。
- [ ] 在设置页关掉一个来源：它的条目从资讯页消失；打开又回来。
- [ ] 把“每天的口令”粘进 Codex 定时任务：到点它取了、写了总结，页面上看得到；之后再加一个来源，不动定时任务，第二天它也会去取新来源。
- [ ] 装过 v1 的工作台 `node scripts/module.mjs update news`：原来的条目、关注词都还在，AI HOT 照旧每天 08:30 自己取。
- [ ] 手机宽度下不左右滚动。
- [ ] 在 Codex 里问“今天的资讯说了什么”：它读到当天的总结，回答里带链接；说“把资讯页打开”，拿到带 `?embed=1` 的地址。

## 12. 给开发的提示

- 参考实现：Skill 的 `modules/news/`（模块包）。从零做的，按工作台模板的规范写（菜单在 `nav.ts`、页面在 `src/features/`、接口挂到 `/api` 下），不要另起一个小网页。
- 写入一律走命令（`server/cli.ts news-add`、`news-digest-set`、`news-source-add`），和网页同一套检查，记进“最近改动”；不直接写数据库。网页只看、开关来源、改关注词。
- 去重：同一个来源里，链接去掉 `utm_*`、`spm`、末尾的 `/` 再比（`#/`、`#!` 开头的留着，有的网站靠它区分哪一篇）；没有链接比“日期 + 标题”。
- 工作台自己取 RSS 时用模板的公共调度（`server/jobs/`），不要自己写 `setInterval`；拆 RSS 不用加依赖（一期是一个 `<item>`，Atom 是 `<entry>`；AIHOT 日报的总结是 description 里第一个 `<p>`，分类是 `<strong>`）。
- 升级只加不删：新表、新字段放新的迁移文件（`m-news-002-…`），旧表和数据留着，旧条目拷进新表时编号不变；用过 v1 的老用户保持原来的取法。
