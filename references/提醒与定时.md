# 提醒与定时

老板不需要懂这些，Skill 按下面的做法全部设好，最后只告诉老板两句话：“第一次打开点允许通知”“电脑开着、不合盖才能按时整理和提醒”。

## 提醒走三条路

| 老板在哪 | 怎么提醒 | 实现 |
|---|---|---|
| 工作台页面开着（在后台标签也算） | 浏览器通知，点一下打开对应页面 | 页面里 `Notification`；服务端经已有的实时通道（SSE）推提醒。127.0.0.1 算安全来源，可以申请通知权限 |
| 页面关了，电脑开着 | 电脑系统通知 | 工作台后台服务直接发：Mac 用 node-notifier（自带 terminal-notifier，可设 `open` 为工作台网址，点通知直接打开）；失败时退回 `osascript -e 'display notification …'`（点了打不开网页，只作兜底）。Windows 用 node-notifier（SnoreToast），`appID` 设为“老板工作台” |
| 不在电脑旁 | 同一条再推到飞书 | 只有接好飞书机器人（或飞书群自定义机器人 webhook）后才开；同样由本机发出 |

共同前提：电脑开着、已登录、没睡眠。合盖、睡眠、关机时都提醒不了；想一直在线要把工作台部署到云上（选做）。

不用浏览器的网页推送（Web Push）：要经过浏览器厂商的推送服务，Chrome 的推送服务在国内网络下时通时断，还要配密钥。

## 提醒什么、怎么不打扰

- 待办到期（当天早上一次、到期前 1 小时一次）、日程开始前 15 分钟、客户到了约定跟进日或太久没联系、数据异常、数据源没按时更新、日报写好了。
- 同一件事一天最多提醒一次；22:00—8:00 只记不弹（老板开机更早就从开机时间开始）。
- 每条提醒都进工作台右上角的通知列表，可以回看。

## 每天几点准备好

确认页里老板回答了两个问题，`result.json` 的 `schedule` 里有 `prepare_at`（开始整理）和 `notify_at`（提醒看）：

1. 工作台后台服务在 `prepare_at` 拉数据（飞书多维表格、导入文件夹、RSS 等）、算异常、准备今日页。
2. 需要 AI 写的部分（经营日报的文字、小红书选题）由 Codex 定时任务在 `prepare_at` 之后 5 分钟运行，通过工作台命令写回。
3. `notify_at` 弹通知：“今天的汇总好了”。
4. 那个时间电脑没开：后台服务启动时检查“今天整理过没有”，没整理就马上补一次，整理好再提醒。
5. `prepare_at` 为空（老板说开机时间不一定）：每次开机 5 分钟内整理，整理好就提醒。

## 开机自动启动

下面的 `<程序位置>` 是工作台程序文件夹（默认 `<知识库>/工作台/程序`；知识库在云盘里时是库外的 `~/老板工作台/<店名>/程序`）。程序在库外时，开机自启也要带上两个环境变量：`WORKBENCH_ROOT`（知识库根目录）和 `WORKBENCH_DB`（`<工作台位置>/数据/workbench.db`），和安装、命令行用的一样；不带的话程序会把“程序文件夹往上两层”当成知识库，读不到知识库、也找不到原来的数据库。程序在知识库里（默认位置）时不用写这两个。

**Mac（登录项服务 LaunchAgent）**：写 `~/Library/LaunchAgents/com.boss-workbench.<文件夹短名>.plist`（短名只用英文字母、数字和连字符）：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>com.boss-workbench.abc</string>
  <key>ProgramArguments</key><array>
    <string>/usr/local/bin/node</string><string>server/index.ts</string>
  </array>
  <key>WorkingDirectory</key><string><程序位置></string>
  <key>EnvironmentVariables</key><dict>
    <key>PORT</key><string>4517</string>
    <!-- 程序在知识库外时才加下面两项，写完整路径 -->
    <key>WORKBENCH_ROOT</key><string><知识库根目录></string>
    <key>WORKBENCH_DB</key><string><工作台位置>/数据/workbench.db</string>
  </dict>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
  <key>StandardOutPath</key><string><程序位置>/日志/服务.log</string>
  <key>StandardErrorPath</key><string><程序位置>/日志/服务-错误.log</string>
</dict></plist>
```

`node` 用 `which node` 的实际路径（Apple 芯片上 Homebrew 装的在 `/opt/homebrew/bin/node`，nvm 装的要写全路径）。`日志/` 文件夹要先建好。加载：`launchctl bootstrap gui/$(id -u) <plist>`；停止：`launchctl bootout gui/$(id -u) <plist>`。

Mac 会拦后台程序读“桌面”“文稿”“下载”和 iCloud 云盘里的文件。程序或知识库放在这些地方时，后台服务第一次读文件可能弹“node 想访问……”，要点允许；没弹框又读不到（日志里有 `Operation not permitted`），就到“系统设置 → 隐私与安全性 → 文件和文件夹”里给 node 打开。装好后重启一次电脑，确认服务自己起来了、能读到知识库。

**Windows（任务计划，登录时运行）**：

任务计划不能设工作目录，所以先在程序文件夹里生成 `启动工作台.bat`（`node` 的路径用 `where node` 查到的那个）：

```bat
@echo off
chcp 65001 >nul
cd /d "<程序位置>"
if not exist 日志 mkdir 日志
set PORT=4517
rem 程序在知识库外时才加下面两行，写完整路径
set "WORKBENCH_ROOT=<知识库根目录>"
set "WORKBENCH_DB=<工作台位置>\数据\workbench.db"
"C:\Program Files\nodejs\node.exe" server\index.ts >> 日志\服务.log 2>&1
```

再建任务：

```powershell
schtasks /Create /TN "老板工作台" /SC ONLOGON /RL LIMITED /TR "\"<程序位置>\启动工作台.bat\"" /F
```

路径里有中文：bat 要存成 UTF-8（不带 BOM），并保留第二行 `chcp 65001 >nul`，否则 Windows 按 GBK 读，`cd` 会找不到文件夹。下面的 vbs 要存成 UTF-16（Node 里 `fs.writeFileSync(路径, '\ufeff' + 内容, 'utf16le')`）。

这样登录时会闪一个黑色命令行窗口并一直开着（关掉它工作台就停了）。不想看到窗口：任务改成运行同目录的 `启动工作台.vbs`，内容一行 `CreateObject("WScript.Shell").Run """<程序位置>\启动工作台.bat""", 0`。也可以把 bat 或 vbs 的快捷方式放进“启动”文件夹（`Win + R` 输入 `shell:startup`）代替任务计划。
