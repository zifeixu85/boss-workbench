# 模块需求文档：报价到回款

> 一句话：给 B2B 设备公司老板周岑用，把每个项目从“询价”管到“尾款收齐”；打开就知道卡在技术、合同、首款还是验收，钱的几个数各是多少。
> 状态：课上范例（按五轮模拟里虚构的“川序气动”写，人和事全部虚构）｜版本：v1
> 适合：卖设备、做工程、做定制方案的 B2B 小公司。和“客户跟进”的区别：客户跟进看“人和关系”，这个看“一单生意的节点和钱”。

## 1. 为什么要做

结论：项目卡在哪、钱到哪一步，散在销售的表、内勤的到账表和老板脑子里，最容易把“报价”“合同”“到账”混成一个数。

- 现在怎么做：销售一张跟进表（客户、跟进人、金额、当前说法、下次联系），内勤一张到账表；技术条件写在便签里。
- 卡在哪：
  1. 首款没到就订了货的风险（内勤专门提醒过“首款没来别订货”）。
  2. 报价、合同额、已到账、尾款混着说。
  3. 验收了不等于尾款收了，常被当成一回事。
- 做完以后：打开一个项目，看到它在哪个节点、在等谁、钱的四个数（报价、合同、已到账、待收）分开列。

## 2. 谁在什么时候用

| 场景 | 谁 | 什么时候 | 想知道或想做什么 |
|---|---|---|---|
| 周一过项目 | 周岑 + 销售 | 周会 | 哪几单卡着、卡在谁 |
| 跟进完记一笔 | 销售 | 每次联系后 | 客户说了什么、下次哪天联系 |
| 核到账 | 内勤 | 收到银行通知 | 记到账，首款到了才放行订货 |
| 定技术边界 | 周岑、工程师 | 报价前 | 哪些条件还没核实 |

## 3. 业务流程

询价初筛 → 工况与现勘 → 方案与报价（可先出附条件预算版）→ 客户内部审批 → 合同 → 首款到账 → 订货排期 → 安装调试 → 客户签收或验收 → 按合同节点收款（可能随保养分期）。

例外：没取得运行数据，报价写明附带条件；客户内部审批的人和采购不是一个人，要分开记；首款没到停在“采购前核对”。

## 4. 关键对象和状态

| 东西 | 要记哪些信息 |
|---|---|
| 项目（一单生意） | 编号、客户、跟进人、内容、当前节点、在等谁、下次联系 |
| 金额 | 报价（含不含税）、合同额、每笔到账（日期、金额、核实人）、待收（= 合同 − 已到账） |
| 条件 | 还没核实的技术条件（例：最大用气量、入口温度、露点要求） |

| 节点 | 进来的条件 | 下一步 |
|---|---|---|
| 询价 | 客户来问 | 拿到运行资料 → 现勘 |
| 报价 | 出了报价（可附条件） | 客户审批 |
| 合同 | 签了 | 等首款 |
| 等首款 | 合同签了、首款没到 | 内勤核到账 → 订货 |
| 实施 | 订货、安装 | 签收 / 验收 |
| 待收尾款 | 验收或签收了，钱没齐 | 收齐 → 结清 |
| 结清 | 合同额全部到账 | — |

规矩：只有内勤核过的才算到账，“客户说已申请付款”不算；改节点写一句原因；验收和结清分开。

## 5. 页面和交互

放在“客户”分区，菜单名“项目与回款”（和客户跟进放一起）。

| 页面 | 第一屏看到什么 | 能做什么 |
|---|---|---|
| 看板 | 按节点分列的卡片，卡上写在等谁、下次联系 | 拖动改节点（要写原因） |
| 项目详情 | 节点时间线、四个钱数、未核实条件、往来记录 | 记一笔、记到账（内勤） |
| 待收款 | 待收的项目和金额、合同约定的节点 | 记到账 |

## 6. AI 帮什么

| AI 做什么 | 结果写到哪 | 要确认吗 |
|---|---|---|
| 从会议纪要、聊天里拆出“下一步、谁做、哪天前” | 往来记录、待办 | 待办先列给周岑看 |
| 提醒“首款没到别订货” | 今日页 | 不用 |
| 改节点、记到账 | 项目 | **要**：先讲清要点，周岑点头再写 |

## 7. 提醒

下次联系到日子；合同约定的收款节点到了还没到账（开了提醒才有）。

## 8. 数据从哪来、存在哪

项目和到账存工作台数据库；第一次从跟进表、到账表导入（老板确认过的行）。知识库放流程规矩、客户档案和判断（比如“什么时候先出附条件报价”）。

## 9. 规矩和边界

- 报价、合同、到账、验收都要周岑确认才写；不替他对客户承诺效果。
- 金额按原列分开说，不合成“收入”。

## 10. 第一版做什么

- 一定要有：看板、项目详情、四个钱数、待收款。
- 以后再说：供应商货期、保养排期。

## 11. 怎么算好

- [ ] 周会上 1 分钟说清每单卡在哪、在等谁
- [ ] 首款没到的项目，看板上明显标出来
- [ ] 网页记的到账，对话里问 AI 读得到；手机宽度能看；`npm run build`、`npm run doctor` 通过

## 12. 给开发的提示

- 参考实现：客户跟进的看板（`src/features/clients/PipelinePage.tsx`）和应收款（`ReceivablesPage.tsx`）。
- 模块开关 id：`deals`；需要 `clients`。
- 表：`deals`、`deal_payments`、`deal_conditions`；改节点留旧值和原因（照客户改阶段的做法）。
- 命令行：`deal-add`、`deal-stage <项目> <节点> --reason`、`deal-pay`（要老板确认的命令在 AI 助手提示词里写清先问）。
