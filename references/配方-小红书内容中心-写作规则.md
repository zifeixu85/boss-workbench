# 配方：小红书内容中心｜写作规则（模块自带）

这是“小红书内容中心”模块的写作规则，不是一个单独安装的 Skill。模块搭好时，把下面“规则正文”放进知识库根目录的 `.agents/skills/xhs-creator/SKILL.md`，开头加上这两行元信息（只在这个知识库里生效，工作台的创作页、每天的选题定时任务都靠它让 Codex 按规则写）：

```yaml
---
name: xhs-creator
description: 小红书创作：按老板知识库里的账号定位、口吻、不能说的话和写法卡，出选题、写图文笔记（标题、正文、话题、封面大字、内页图）、改标题和开头、做小红书数据复盘（“复盘一下上周的小红书”）；老板只说一句话（“写一篇降温喝白茶的”“再给 3 个标题”“明天写什么”）。工作台“小红书内容中心”的创作对话和每天早上的选题定时任务也用它，回复里带工作台能解析的 draft / options / topics / review 标签块。只写草稿，不登录小红书、不替老板发布。知识库的“复盘一下”“最近有什么发现”用 boss-kb。
---
```

加这个模块时，先和老板立项对焦、定好需求文档（案例见 `需求文档-小红书内容中心.md`），再让工作台把模块和这份写作规则一起做出来。老板的账号定位、口吻、不能说的话、写法卡都在知识库里，这份规则只管“怎么读这些、怎么交稿”。

## 规则正文

## 小红书创作

老板只说一句话，其余的由这个 Skill 和老板的知识库补齐：先判断这次是什么任务，再读对应的资料，最后交出结构化的稿件。

### 先读什么（按需，不要全读）

1. 知识库根目录的 `AGENTS.md`：看地图，和“常见任务先读哪里”里“写小红书”那一行；有这一行就照它的顺序读。
2. `03-生意/品牌与口吻.md`：定位、写给谁、口吻、**不能说的话**——每次都读。红线按其中 `## 不能说的话` 那张表（表头 `| 类别 | 不说 | 换成 |`）逐行核。
   - 找不到这份文件，或者里面没有这张表：改读 `02-关于我/边界.md`（私密，只拿来核，不写进稿子和说明）和账号定位，按通用红线（功效、极限词、贬低别家）核，**不自己编红线词**；说明末尾提醒一句：“你的知识库里还没有‘不能说的话’，可以用 boss-kb 补。”
3. 内容模块（生长模块，编号因人而异，按 `01-AI协作/建库档案.md` 的“启用的模块”找；ABC茶社是 `11-内容与作品/`）：先读它的 `README.md` 和账号定位（如 `小红书账号定位.md`：写给谁、内容支柱），再看 `规律/` 和 1—3 篇代表作卡。查发过什么用 `作品索引.md`；不通读原文。
4. 写法卡：`05-方法与判断/README.md` 的方法选择表 → 小红书那一类（常见位置 `05-方法与判断/小红书内容/`），按它的表挑 1—3 张。
5. 写到具体产品、价格、上新时间时，读 `03-生意/产品与服务/` 和对应的项目文件；**只用知识库里有的事实**。
6. 有数据快照就读（常见位置 `工作台/快照/小红书近60天表现.md`）：哪类内容收藏高、最近发得少。

旧格式知识库：品牌口吻和小红书定位都在 `生意/品牌与内容.md`，方法在 `资料/` 下。

### 判断这次是什么任务

| 老板说的 | 任务 | 交付 |
|---|---|---|
| “出几个选题”“明天写什么” | 选题 | `<topics>` |
| “写一篇……”“就做这个” | 写一篇 | `<draft>` |
| “再给 3 个标题 / 开头换一个 / 短一点” | 改稿 | `<options>` 或新的 `<draft>` |
| “做个封面”“内页图怎么排” | 封面和图片页 | `<draft>`（只改 cover_text 和 pages） |
| “复盘一下上周的小红书”“这周笔记数据怎么样” | 小红书数据复盘 | `<review>` |

不清楚就按“写一篇”处理，并在说明里问一句最关键的。

### 怎么挑写法卡

写法卡每张写着“适合什么任务 → 怎么做 → 交付什么 → 例子 → 别这样做”。按方法选择表挑：办公室场景类选“场景开头”，清单收藏类选“清单图文”，新品预热选“新品预热”那张。说明里写清“按《xxx》写的”；卡还是“待确认”的，也说一句。

知识库里还没有小红书写法卡时，用下面的通用写法，并在说明末尾提醒一句：“你的知识库里还没有小红书写法卡。可以用 boss-kb 补访写法卡，或者借别人公开的写法卡来试，写清出处。”借来的卡标“试用中”。

### 通用写法（没有写法卡时的底线）

- 标题 20 字以内，先说场景或结果，可以带数字；给 3 个备选，各用不同角度（场景 / 反常识 / 清单）。
- 开头两句先说具体场景（加班、午后犯困、开会前……），再说解决办法。
- 正文 300—600 字，短句、口语、用“你”；步骤用 1、2、3；不堆形容词。
- 话题 5—8 个：品类词 + 场景词 + 人群词。
- 封面大字 12 字以内；图文笔记配 3—6 张图片页：封面一句大字，内页每页一个要点。
- 结尾一句互动问题。

### 不编造、守红线

- 价格、规格、成分、上新时间只用知识库里有的；没有就写“【待补：××】”，不要猜。
- 写完自己核一遍：品牌与口吻里“不能说的话”（功效、极限词、贬低别家等）、企业客户的名字、还没上线的新品名、AI 腔句式（“不是……而是……”“总而言之”“赋能”）、后台字眼（文件路径、“知识库”“Skill”）。改过的地方在说明里列出来。
- 用了写法卡的，按这次用的每张卡里“别这样做”逐条核一遍，每条的结果写进 `draft.checks`（如 `{"item":"《场景开头》别这样做：开头先夸产品","result":"已改成先讲加班犯困"}`）。
- 不登录小红书、不批量抓取、不替老板发布。

### 输出格式（工作台靠它解析，必须照写）

先用 2—5 句话说明这次怎么写的、参考了哪些文件，然后附一个标签块：

```text
参考了：03-生意/品牌与口吻.md、11-内容与作品/小红书账号定位.md、05-方法与判断/小红书内容/场景开头.md

<draft>
{"format":"图文","titles":["降温了！办公室一个杯子泡白茶的 3 种方法","……","……"],"title":"降温了！办公室一个杯子泡白茶的 3 种方法",
 "cover_text":"降温了 办公室一个杯子泡白茶",
 "pages":[{"role":"封面","text":"降温了\n办公室一个杯子泡白茶"},{"role":"内页","text":"方法 1：先温杯"}],
 "body":"……","tags":["办公室泡茶","白茶"],
 "checks":[{"item":"不能说的话","result":"已把“养胃”改成“暖暖的”"}]}
</draft>
```

- 选题：`<topics>[{"title":"…","source":"评论区|热点节气|同行爆款|知识库","reason":"为什么现在写","pillar":"内容支柱"}]</topics>`
- 候选：`<options>[{"text":"…","note":"角度"}]</options>`
- 复盘：`<review>{"summary":"…","worked":["…"],"change":["…"],"ideas":[{"title":"…","reason":"…"}],"learnings":[{"rule":"…","evidence":"哪几篇"}]}</review>`

JSON 必须能直接解析（双引号、不加注释）。一次只放一个标签块。复盘里的 `learnings` 只是候选：老板点头后追加到 `90-持续生长/待确认的发现.md`，由 boss-kb 整理进规律或写法卡，这里不直接改知识库。

### 每天早上的选题（定时任务用）

“每天早上给我 10 个小红书选题”（几点由定时任务定，示例是 07:00）：读账号定位、作品索引里最近 30 天发过的（避免重复）、`04-客户/客户原话与顾虑.md` 和评论区常被问的问题，再联网搜公开的热点和节气；输出 `<topics>`。写回工作台用工作台的命令（见 `工作台/README.md`，例如在程序文件夹里运行 `node server/cli.ts xhs-topics-add --file <json>`）；没有这个命令就存到 `工作台/导入/小红书选题/<日期>.json`。
