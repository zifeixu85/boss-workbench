# 只读版怎么做

## 1. 上线的到底是什么

本地工作台不动，照旧跑在 127.0.0.1。上线的是一个“手机看板”：

```
工作台（本机） --today/clients --json--> export_snapshot.mjs --打码快照、上传清单、对照表（工作台/手机版/）
   --> build_page.mjs（加密前先查正文）--> dist-mobile/index.html --check_dist.mjs（带快照）
   --> 静态网站托管 m-xxxxxxxx/ --> 手机打开
```

- **不是实时的**：手机上看到的是导出那一刻的数据。更新就再走一遍（说“更新手机版”）。
- **只能看，不能改**：页面不连任何接口，没有新增、修改按钮。
- **不是登录保护**：拿到链接的人都能打开；加了口令锁的，没口令看不到内容。

别的路线不在本 Skill 里做：登录才能看（CloudBase 身份认证加云数据库权限规则）需要另做登录保护版（本 Skill 不含）；整套工作台搬上云（SQLite 改云数据库、服务放云托管）不做；绑自己的域名要升级付费版、域名要 ICP 备案，只跟老板提一句。

## 2. 放哪些

数据来自工作台的 `today --json`（今日概况）和 `clients --json`（客户列表，只用来打码，不上传）。**只挑下面白名单里的字段**，其余一律不进快照。

老板没点名放哪几块时，导出脚本在默认的五块里**只放今天有内容的**：每个老板在确认页挑的模块不一样，没有这个模块、或者今天是空的，就不放（清单“没放的”里写明原因），手机上不会出现空卡。真实数据第一次上线，Skill 默认只放“待办、日程”。

| 块（`--sections` 写法） | 默认 | 放的字段 | 不放 |
|---|---|---|---|
| 待办 | 放 | 最该做的一件事；今天和逾期的、这周的：事情、截止日、紧急程度、状态、相关客户（化名）、逾期天数 | 备注 |
| 日程 | 放 | 今天和接下来几天：时间、事情、类型、相关客户（化名） | 地点、备注、来源 |
| 跟进 | 放 | 重点客户：化名、阶段、跟进理由（最多 3 条）、下一步；快到跟进日的：化名、阶段、计划日、逾期天数 | 联系人、电话、标签、沟通原文、累计消费 |
| 风险 | 放 | 项目名、风险等级和说明 | 负责人 |
| 小红书 | 放 | 今天和后三天要发的笔记标题、时间、状态；今天的选题标题 | 粉丝数、笔记数据、草稿正文 |
| 经营 | **不放** | 各平台比前天涨跌、退款率、ROI、异常标题；加 `--amounts` 才放成交额和订单数 | 推广花费、访客、渠道负责人、异常详情 |
| 钱 | **不放** | 应收总额、逾期金额和笔数、30 天内到期金额（万元）；必须加 `--amounts` | 每笔应收、客户名、账本 |

模板以后加了新模块，想在手机上看，先用本 Skill 的“加模块”（见 `加减模块.md`） 让它出现在工作台的今日概况里，再在这里加一块（改 `lib.mjs` 的 `SECTIONS` 和 `buildSnapshot`，`build_page.mjs` 加一个渲染函数，配测试）。

## 3. 怎么打码

所有文字字段都过一遍打码器（`lib.mjs` 的 `buildMasker`），顺序是：

1. **客户和合作方**：全名换成代号（客户A……客户Z，第 27 个起用数字：客户27，免得“客户AB”被读成“A 和 B”；按客户 ID 排序，同一个客户每次导出代号不变）；或者首字（衡**）。客户的简称一起换：去掉开头的地名、结尾的行业词（“云杉律师事务所”→“云杉”），再加上前两个字。合作方只换全名，不取简称（免得“武夷岩茶厂”把茶名“武夷岩茶”也换掉）。个人客户（三个字的名字）连名一起换（“方雅琴”“雅琴”）。
2. **联系人**：工作台里记的联系人、称呼、决策人。带称呼的换成“某老师”“某经理”，不带的换成“联系人”；个人客户的称呼换成他的代号。
3. **同事**：经营数据里的渠道负责人自动当同事，换成“同事”。
4. **老板补充的名字**：`--extra-names "小艾,老何=设计师"`，没写换成什么就换成“某人”。
5. **姓加称呼**：王总、宋姐、吴老师这类换成“某总”“某姐”“某老师”（“周总结”“汇总”这类不误伤）。首字模式下不换。
6. **隐私号码**：手机号（含已经打了星号的）、座机、身份证号、邮箱、微信号、带门牌号的地址（“江南大道 588 号 3 栋”这种中间带空格的也认），换成“（电话已隐藏）”这类字。
7. **金额**（不加 `--amounts` 时），宁可多遮：
   - 带单位的：“1.6 万”“¥1,280”“300 元”“1.6w”“3k”“200块”换成“×× 万”“¥××”“×× 元”“××w”；“欠款1万2”整段换成“欠款××万”。
   - 钱字眼后面的数字：预算、报价、单价、客单价、尾款、货款、欠款、成交、价……后面的数字换成 ××（“预算 3000 左右”“客单价 680”“价 80 一盒”）。
   - 没单位的三位以上数字也遮（“推经典双罐 180（不超 200）”→“××（不超 ××）”）。
   - 不动的：数量（6 盒、2500 袋、300 份）、百分比、日期（10/31、2026-10-27）、时间（19:30）、“第 4 个”、年份。

**自动打码认不全**：不在客户列表里的人名、外号、少见简称、长句里的地址。上传清单最上面有“最该看的几处”：像人名的叫法（小X、老X、阿X，只列出来、不自动换）、还带数字的条目、像地址的条目。老板先看这几处，再从头看“会上传的全部文字”，发现漏的就补进 `--extra-names` 重导。

对照表 `工作台/手机版/对照表-<日期>.json` 记着“化名 ← 原名”，只在本机：老板想知道“客户F 是谁”时查它；`build_page.mjs` 和 `check_dist.mjs` 都用它查有没有漏掉的真名。**它永远不上传。**

手机版的文件都放 `工作台/手机版/`，不放 `工作台/快照/`：那个文件夹是工作台自己导出的“今日概况、客户现状”，别的对话会去读；对照表里有真名，不该混在那里。数据库备份也不在 `工作台/快照/`，在程序文件夹里的 `备份/`（见 `加减模块.md` 第 4 步）。记录写在 `工作台/手机版/记录.md`，不改 `工作台/README.md`（上线手机版不改 README）。

## 4. 怎么关掉写入（自带的 `build_page.mjs`）

- 只产出一个 `index.html`，样式写在页面里，不引用任何外部文件、字体、统计代码。
- 页面里写了内容安全策略：`connect-src 'none'`（不连任何接口）、`form-action 'none'`（表单发不出去）、不加口令锁时 `script-src 'none'`（一行脚本都不跑）；加口令锁时只允许那一段解密脚本（按哈希放行）。
- 没有新增、修改、删除按钮，没有输入框（口令框除外）。
- 加了 `noindex`（不让搜索引擎收录）和 `no-referrer`（点别的链接时不带出本页网址）。
- 字体用系统字体（苹方、微软雅黑），不用宋体；手机竖屏优先，自动跟随深浅色。

## 5. 模板内置 `build:mobile`：本期不做

之前设想过让工作台模板内置一条只读打包命令，手机版能和电脑上长得一样。**本期不做，Skill 只走自带的 `build_page.mjs` 一条路**，理由：

- 只走一条路，好教也好排查；
- 整套前端打包会带上所有模块的代码和接口调用，自检很难全覆盖；
- 口令锁得在模板里再做一遍，加密前查正文这道闸门也得再做一遍（之前的约定里漏了这一点：加锁后自检看不到正文）。

以后要做，再按“只从快照读、相对路径、哈希路由、隐藏所有写入入口、加密前查正文、能过 `check_dist.mjs`”重新定约定。

## 6. 访问保护

静态网站托管本身**没有访问密码**。IP 白名单要企业版起，手机网络的 IP 又经常变，用不上。本 Skill 能做的是下面几层，跟老板说清楚各挡得住什么：

| 一层 | 挡得住 | 挡不住 |
|---|---|---|
| 打码（默认） | 链接被转出去时，别人看不到客户真名、电话、金额 | 看得到打码后的待办和日程 |
| 随机文件夹 `m-xxxxxxxx` | 只知道域名的人猜不到页面在哪 | 拿到完整链接的人 |
| 口令锁（建议加） | 没口令的人看不到内容：内容是用口令加密后放进页面的，页面源代码里也只有一串乱码 | 口令太短（尤其是纯数字），懂技术的人能拿到页面后慢慢试出来；它也不是登录系统，不能按人收回权限——要收回就换口令重新上传，或撤下。解密脚本靠页面里写死的“脚本指纹”放行，平台或加速节点改了网页内容就打不开（还没实测） |
| 链接不外传 | —— | 靠人自觉；所以前几层不能省 |

口令规则：至少 6 个字，建议一句只有你们知道的短话（“周三下午喝白茶”）；纯数字会被提醒。口令不写进工作台、知识库、网页文件和记录，**但会留在本机 Codex 的对话记录里**（老板在对话里说的、命令里用的都在），所以别用在别处用过的密码。告诉别人时单独说，别和链接放在同一条消息里。

**加锁以后，上传前的自检看不到正文**（正文加密了）。所以两道闸门都改了：`build_page.mjs` 加密之前先用对照表和号码规则查一遍正文，查到就不打包；`check_dist.mjs` 要带 `--snapshot`，查快照里的字，并核对页面是不是用这份快照打的。

真正的“登录才能看”（每个人自己的账号、能收回）：用 CloudBase 身份认证加云数据库权限规则，数据放云数据库、前端先登录再读。步骤多、要配权限和发布密钥，需要另做登录保护版（本 Skill 不含；可以参考插件里的 `auth-web-cloudbase`、`minimal-web-baas-demo` 技能）。

## 7. 上传前自检（`check_dist.mjs`）

| 拦下（必须改） | 提醒（看一眼） |
|---|---|
| 数据库（`.db` `.sqlite` 及 `-wal` `-shm`）、`.env`、Markdown、源代码（`.ts` `.tsx` `.jsx`）、source map、表格、文档、压缩包、配置和密钥文件 | 邮箱样的字符串（可能是第三方库里的） |
| `node_modules`、`.git`、`server`、`src`、`数据`、`快照` 这类文件夹 | 连本机接口的代码（`127.0.0.1`、`localhost:端口`、`/api/`） |
| 快捷方式（链接文件） | 图片（确认没有客户照片、聊天截图、收款码） |
| 手机号、身份证号、腾讯云 SecretId、SecretKey 字样、私钥、`sk-` 开头的密钥 | `.json` 文件（确认没有原始数据） |
| 对照表里的真名（中文被打包成 `\u8861` 这种写法也能查到） | 包超过 5 MB |
| 最外层没有 `index.html`；HTML 里用“/”开头的绝对路径引用文件 | 没给对照表、没查真名 |
| 整个包超过 50 MB | 页面里没有快照指纹，没法核对 |
| 页面加了口令锁却没带 `--snapshot`；快照里查到上面这些；页面和快照对不上 | |

报告里查到的号码、密钥只显示前几位，不把原文打到对话里。

## 8. 快照文件格式（`boss-workbench/手机版快照/1`）

```json
{
  "format": "boss-workbench/手机版快照/1",
  "title": "手机看板",
  "data_date": "2026-10-27",
  "generated_at": "2026-10-10 10:30",
  "rules": { "sections": ["todos", "events", "follow", "risks", "xhs"], "alias": "代号", "amounts": false, "lock": "有",
             "masked": { "clients": 28, "partners": 4, "contacts": 24, "staff": 3, "extra": 2 } },
  "headline": { "title": "给客户F出两款升级包装效果图（明天要发）", "due": "2026-10-27" },
  "todos": { "today": [{ "title": "…", "due": "…", "status": "…", "priority": "紧急", "client": "客户F", "overdue": 0 }], "week": [], "open_total": 21 },
  "events": { "today": [{ "date": "…", "time": "10:00", "end": "10:30", "title": "…", "kind": "内部", "client": null }], "upcoming": [] },
  "follow": { "key": [{ "name": "客户R", "stage": "待复购", "next_follow": "…", "next_step": "…", "reasons": ["…"] }], "due": [] },
  "risks": [{ "name": "…", "client": null, "items": [{ "level": "高", "text": "…" }] }],
  "xhs": { "posts": [], "upcoming": [], "topics": [], "topics_total": 0 },
  "biz": { "date": "…", "total": { "vs_prev": -13.8 }, "channels": [{ "name": "抖店", "vs_prev": -12.5, "refund_rate": 3.3, "roi": 2.93 }], "alerts": [{ "level": "高", "title": "…" }] },
  "cash": { "unit": "万元", "outstanding": 3.09, "overdue_amount": 0.85, "overdue_count": 2, "due_30": 2.24 }

```

没选的块整块不出现（不是空值）。`biz` 里只有加了 `--amounts` 才有 `gmv`、`orders`。`rules.lock` 是导出时 `--lock` 写的“有 / 无”，打包时核对；没写就没有这一项。
