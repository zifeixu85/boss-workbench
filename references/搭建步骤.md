# 搭建步骤（按 result.json 搭）

全程边做边告诉老板做到哪了（“正在装依赖，大约 3 分钟”）。任何一步失败：说清卡在哪、试过什么、下一步怎么办，不要悄悄跳过。

## 0. 准备

- 读 `result.json`；老板改过的复述（`profile_fixes`）和补充（`extra`）优先于知识库里的说法。
- 检查模板：本 Skill 文件夹里要有 `template/`（工作台模板单独发布，放进本文件夹后才能搭；里面的 `README.md` 写了安装、命令和模块）。没有就停下，告诉老板“工作台模板还没装好”，不要自己从零写一个。
- 检查环境：`node -v` 要 22.18 以上（工作台用 Node 自带的 SQLite 和直接运行 TypeScript，不需要编译原生模块）；没有就请老板去 nodejs.org 下载长期支持版（国内慢用 npmmirror.com/mirrors/node/）。
- 定位置：默认是知识库根目录下的 `工作台/`。下面两种情况，程序和数据库改放库外不同步的位置（Mac：`~/老板工作台/<店名>/`；Windows：`%USERPROFILE%\老板工作台\<店名>\`），备份跟着数据库也在库外（`<工作台位置>/数据/备份/`），`工作台/` 里只放说明和快照：
  - `kb_scan` 的 `cloud_synced` 为 true（iCloud、OneDrive、网盘同步目录）；
  - `cloud_maybe` 为 true（知识库在 Mac 的“桌面”或“文稿”里，读不到 iCloud 设置）：问老板一句“这台 Mac 开了 iCloud 的‘桌面与文稿’同步吗？”，说不清就按开了算。
- `<店名>` 里别用 `/ \ : * ? " < > |` 这些字符，Windows 不认。
- 告诉老板：接下来装依赖、往知识库外面建文件夹、设开机自启时，Codex 会弹几次“是否允许”，都点允许。

## 1. 复制模板

Mac 和 Windows 都能用的写法（路径加引号）：

```bash
node -e "require('fs').cpSync(process.argv[1], process.argv[2], { recursive: true })" "<本 Skill 文件夹>/template" "<工作台位置>/程序"
```

模板里不带依赖包（node_modules）、构建好的网页（dist）和数据库，下一步装。别在模板文件夹里直接装或启动。

## 2. 装依赖、建数据库

```bash
cd "<工作台位置>/程序"
node scripts/install.mjs          # 检查 Node 和端口 → 测官方源和国内镜像哪个快 → 装依赖（失败自动换源）→ 构建网页 → 建空数据库
```

- 装不上：先 `node scripts/install.mjs --check`（= `npm run doctor`）看体检结果，日志在 `程序/install.log`；网络不行加 `--mirror` 直接用国内镜像，或 `--registry=<地址>` 指定源。
- 端口默认 4517。体检只会提示端口被占用，不会自己换：被占了就挑一个空的（如 4527），启动时加 `PORT=4527`，写进 `工作台/README.md` 和开机自启的配置。
- 程序放在知识库外面时（第 0 步那两种情况），安装、启动、命令行都要带 `WORKBENCH_ROOT="<知识库根目录>"` 和 `WORKBENCH_DB="<工作台位置>/数据/workbench.db"`；不带的话，程序会把“程序文件夹往上两层”当成知识库。
- 演示模式：`node scripts/install.mjs --demo` 装好后写入 ABC茶社 示例数据（全部虚构），“今天”固定 2026-10-27；启动时 `DEMO_TODAY=off` 换回真实日期。已有老板自己的数据库时 `--demo` 会停下，不会覆盖。给老板搭的工作台不加 `--demo`。

## 3. 从知识库导入

用工作台命令导入，不直接写数据库（命令写法以模板的 `server/cli.ts` 为准）：

- 客户：读 `04-客户/README.md` 的索引和每个客户文件的开头（名称、分组、阶段、联系人、上次联系、下次跟进），用 `client-add <名称> --label <一句话> --stage <阶段> --next <下次跟进> --kb <客户文件路径>` 建；喜好、重要日子、买过什么、答应过什么，挑要紧的写进备注（`client-set <客户> --note …`）。长段的背景不复制，`--kb` 记下原文件，详情页的“背景笔记”直接读它。
- 项目：`06-项目/` 里 `类型: 项目` 的文件 → `project-add <名称> --stage <阶段> --due <截止> --owner <负责人> --goal <目标> --kb <项目文件路径>`，关键日期每个写一次 `--milestone "2026-11-05 四平台上线"`。
- 待办：`06-项目/近期要事.md` 里没做完的（`- [ ]` 待办和 `- [/]` 进行中，后者加 `--status 进行中`）→ `todo-add <事情> --due <日期> [--client 客户] [--project 项目]`；客户、项目文件里的“下一步”“答应过的事”也建成待办，用 `--note "来源：<文件路径>"` 标来源。导入后待办以工作台为准；要不要在近期要事开头加一句“工作台建好后以工作台为准”，交给 boss-kb，或请老板确认后再写。
- 收件箱：`00-收件箱/` 里还没整理的材料，每份在工作台收件箱记一条，带上判断，不只放文件名：`inbox "<文件名>：一句话说是什么" --kind 材料 --why "这是谁的、讲了什么要紧的" --suggest "建议怎么整理" --from "00-收件箱/<文件名>"`（认得出客户的加 `--client`）。装了客户与跟进模块时，“新材料提取”页会直接列出这些文件，点开就是原文。
- 生长模块（经营、内容、达人……）：按建库档案“启用的模块”表找到文件夹，读它的 README 和口径文件，只导入档案和口径；每天的数据稍后接。
- 知识库页：只读显示各层 README 和文件，不复制。
- 旧格式知识库：客户在 `生意/客户/`，项目在 `生意/项目/`，待办在 `生意/近期要事.md`，新材料在 `原始材料/`（`采访记录/` 除外）。

导入完跑 `node server/cli.ts today` 核对，数量和确认页里说的对得上。

## 4. 按选择配置

- 模块：用模块开关只打开 `result.modules` 里的，不改代码：

  ```bash
  node server/cli.ts settings-set --modules today,tasks,inbox,reminders,kb,<老板选的其他模块>
  ```

  - 确认页的 id 和开关的 id 一样（`today`、`tasks`、`inbox`、`clients`、`projects`、`kb`）；经营看板 `biz`、内容中心 `content` 不在搭建时打开（2026-10-13 定），老板提了就记进“以后想加”，搭好后立项对焦再 `modules --on`；`reminders`（提醒）一直带上；`design`（组件规范）不带。
  - 今日、设置一定开着；以后打开 `biz` 或 `content` 会自动带上 `data`（数据源与导入）。
  - 模板里还没有的（`money`、`weekly`、`news`、`team`、`creators`、`members`）不写进命令，记进 `工作台/README.md` 的“以后想加”，搭好后按 `加减模块.md` 做。命令里写了模板没有的 id 会报错，不会悄悄忽略。
  - 没选的模块代码和数据都留着，以后 `node server/cli.ts modules --on <id>` 或网页“设置 → 模块”就能打开。“稍后接数据”的模块打开着，页面上有空状态说明（“接上数据后这里显示……”）。
- 首页：今日页按老板“最想先看到”（`result.wants`）的顺序排卡片。
- 配色：`result.theme`（jade / wood / navy / mono / night），用 `settings-set --theme <配色>` 写进设置；老板的称呼、店名、小红书账号名同一条命令写（`--owner`、`--business`、`--xhs`，按知识库：称呼看 `02-关于我/`，店名看 `03-生意/`，账号名看 `11-内容与作品/` 的账号定位；没有小红书就不写 `--xhs`，跟店名）。首页问候、标题、给 Codex 的提示词、小红书手机预览都用它们，不要在代码里写死。
- 导航：按 `references/模块目录.md` 的规则定（不超过 8 个模块用简单导航），`settings-set --nav simple|complex|top` 写进设置；菜单项在 `src/app/nav.ts`。
- 老板的补充：`profile_fixes` 和 `extra` 写进 `工作台/README.md` 的“老板的补充”一节；`custom_request` 写进同一份 README 的“以后想加”，搭好后按 `加减模块.md` 做。

## 5. 提醒、定时、开机自启

规则和做法见 `references/提醒与定时.md`（模板已经做好，这一步只设时间、开自启）。在 `<工作台位置>/程序` 里运行（程序在库外时照样带 `WORKBENCH_ROOT`、`WORKBENCH_DB`）：

```bash
node server/cli.ts remind-set --at 8:30                # 每天看汇总的时间 = result.json 的 schedule.notify_at；为空写 --at none（开机 5 分钟后提醒）
node server/cli.ts remind-set --quiet 22:00-08:00      # 免打扰；老板开机比 8 点早，结束时间改成开机时间（--quiet 22:00-07:30）
node scripts/install.mjs --autostart on --name <英文短名>   # 开机自启：马上在后台启动，以后登录自动开（Mac LaunchAgent / Windows 任务计划）
node scripts/install.mjs --autostart status            # 确认：开着、在运行、网页能打开；记下日志位置写进 README
node server/cli.ts remind-test                         # 发一条测试的电脑系统通知（标题“老板工作台 · 测试”）
```

- 跑 `--autostart on` 之前先关掉手动开着的工作台（不然它只写配置、下次登录才生效）；Codex 会问一次“是否允许”。
- `remind-test` 之后问老板看到没有：Mac 没看到就打开“系统设置 → 通知 → 脚本编辑器”的允许通知；Windows 打开“设置 → 系统 → 通知”里 Windows PowerShell 的通知。
- 打开工作台后请老板点今日页顶上的“开启提醒”，浏览器问时点“允许”（页面开着时就用浏览器通知，点了能直接打开对应页面）。
- 需要 AI 写的部分（经营日报、小红书选题）建 Codex 定时任务，时间用 `schedule.prepare_at`，提示词写进 `工作台/README.md`，方便老板以后改。

## 6. 写说明、改入口

- `工作台/README.md`：地址、怎么打开、程序在哪（库外时写完整路径）、备份在哪（数据库旁边的 `备份/`：`node server/cli.ts backup` 存的数据库备份，和工作台改知识库前存的原文件 `备份/知识库/`；库外时写完整路径）、模块清单、每天几点整理和提醒、常用命令（today、client、log、todo-add、backup、reminders、remind-set）、《怎么停、怎么删》（暂停提醒、关开机自启、停后台服务、日志在哪、卸载两个 Skill；模板说明里有现成的一段）、改动记录、老板的补充。
- 知识库根目录 `AGENTS.md`：把要加的内容先给老板看，他说“确认”再写。放在 `<!-- 本段结束 -->` 之后、`## 我加的规矩` 之前，用 `<!-- 工作台 开始：由老板工作台 Skill 维护 -->` 和 `<!-- 工作台 结束 -->` 包住，不超过 6 行，写：工作台网址、程序在哪、“查或改工作台数据先读 `工作台/README.md`，用工作台命令，不直接改数据库”、“进内容先拆再问：待办问清谁做、哪天前，一张清单确认后用 `apply` 一次写入”。AGENTS.md 里已经有“`工作台/` 是程序和数据”那一句的，不重复写。别的段落一个字不动。
- 根目录 `.ignore` 加一行 `工作台/`（没有这个文件就新建）。

## 7. 验收

- `npm run doctor` 通过；每个选中的模块页打开一遍，不报错、有数据（稍后接数据的显示说明）。
- 用浏览器打开首页给老板看；手机宽度也看一眼。
- 对老板说三句话：首页放了什么、每天几点提醒、哪里不满意直接在 Codex 里说。
